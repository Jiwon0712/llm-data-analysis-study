## 1. 프로젝트 제목

**한국어 일본 여행 브이로그의 조회수 관련 요인 분석: 제목·영상 길이·업로드 시점·썸네일 문구를 중심으로**

---

## 2. 프로젝트 배경 및 목적

### 관심 현상

한국어로 제작된 일본 여행 브이로그는 유튜브에서 인기 있는 콘텐츠이지만, 같은 주제의 영상이어도 조회수는 수백 회에서 수백만 회까지 크게 차이 난다. 이 조회수 차이가 어떤 요소와 관련되어 있는지 알아보고자 한다.

### 분석 이유

크리에이터는 제목, 영상 길이, 업로드 시점, 썸네일 등을 직접 선택할 수 있지만, 그 선택이 조회수와 어떤 관계인지는 경험과 감에 의존하는 경우가 많다. 조회수는 채널 규모와 업로드 후 지난 시간의 영향도 크게 받으므로, 이 두 요인을 통제한 뒤에도 크리에이터가 조절할 수 있는 요소가 조회수와 관계가 있는지 확인한다. 또한 이 요소들을 업로드 전에 알 수 있는 정보로 삼아, 조회수 상위권 영상을 구분할 수 있는지 분석한다.

### 프로젝트 목적

일본 여행 브이로그의 조회수와 관련된 요인을 데이터로 확인하고, 업로드 전 정보만으로 상위권 영상을 어느 정도 구분할 수 있는지 검증한다.

### 활용 대상

일본 여행 브이로그를 업로드하려는 크리에이터가 제목, 영상 길이, 업로드 시점을 정할 때 참고하는 자료로 활용할 수 있다.

### 분석의 범위와 한계

- 분석 범위가 일본 여행 브이로그로 한정되어 있어 다른 유튜브 콘텐츠에 적용하기는 어렵다.
- 영상 내용, 출연자, 편집 방식처럼 조회수에 영향을 줄 수 있는 요소가 많지만, 변수로 만들기 어렵거나 프로젝트 범위를 넘어서므로 제외하였다.
- 분석 결과는 인과관계가 아니라 관련성으로 해석한다.

## 3. 핵심 분석 질문

**Q1. 기술형**
일본 여행 브이로그의 조회수는 여행지 종류, 업로드 요일, 업로드 시간대에 따라 어떻게 다른가?

**Q2. 관계형**
채널 구독자 수와 업로드 후 경과 일수를 통제한 뒤에도, 제목 길이, 영상 길이, 썸네일 문구 유무는 조회수와 관계가 있는가?

**Q3. 예측형**
업로드 전에 알 수 있는 정보만으로 조회수 상위권 영상을 얼마나 구분할 수 있는가? 업로드 전에 알 수 있는 정보는 제목 길이, 여행지 종류, 영상 길이, 업로드 요일과 시간대, 썸네일 문구 유무, 구독자 수이다. 상위권은 수집한 영상 중 조회수가 상위 25%에 드는 영상으로 정의한다.

## 4. 데이터 확보 계획

### 데이터 출처

YouTube Data API v3, Google 공식 API

### 접근 방법

공식 문서 주소는 https://developers.google.com/youtube/v3 이다. Google Cloud Console에서 프로젝트를 만들고 YouTube Data API v3를 사용 설정한 뒤 API 키를 발급받았다. 키는 YouTube Data API v3로만 사용하도록 제한하였으며, `.env` 파일로 분리하여 GitHub에 올리지 않는다.

### 수집 방법

1. `search.list`로 검색어 8개를 검색하여 영상 ID를 수집한다. 검색어는 일본 여행 브이로그, 도쿄 브이로그, 오사카 브이로그, 교토 여행 브이로그, 후쿠오카 브이로그, 일본 혼자 여행, 일본 자유여행 브이로그, 일본 소도시 여행이다. 영상 유형은 video, 지역은 KR, 관련 언어는 ko로 하고 검색어마다 2페이지, 최대 100건을 받는다.
2. 검색어 사이에 겹치는 영상은 영상 ID 기준으로 제거한다.
3. `videos.list`로 영상별 제목, 업로드 시각, 영상 길이, 조회수, 채널 ID, 썸네일 주소를 가져온다.
4. `channels.list`로 채널별 구독자 수를 가져온다.
5. 경과 일수를 계산하기 위해 수집일을 함께 기록한다.

### 표본 선별 조건

- 영상 길이가 3분 미만인 숏폼은 제외한다.
- 수집일 기준 업로드 후 2년이 지난 영상은 제외한다.
- 업로드 후 7일 미만인 영상은 조회수가 아직 쌓이는 중이므로 제외한다.
- 일본 거주자의 일상 영상, 광고, 일본 여행과 무관한 영상은 제목과 채널 정보를 확인하여 제거한다. 판단이 불확실한 영상은 포함한다.

### 예상 데이터 규모

테스트 수집에서 고유 영상 661건을 확보하였고, 숏폼을 제외하면 485건, 384개 채널이다. 선별 조건을 모두 적용한 최종 분석 대상은 약 350건으로 예상한다.

### 실제 확보 가능 여부

- 검색어 8개와 검색 16회로 고유 영상 661건을 확보하였다.
- 숏폼 제외 후 남은 485건, 384개 채널에서 조회수와 구독자 수를 모두 확인하였다. 구독자 수를 숨긴 채널은 없었다.
- 485건 중 최근 2년 이내 영상은 448건이고, 업로드 후 7일 미만 46건을 제외하면 402건이다.
- 무작위로 뽑은 50건을 직접 확인한 결과 일본 여행 브이로그로 명확히 판단되는 비율이 약 88% 이상이었다. 이를 적용하면 최종 분석 대상은 약 350건이다. 표본이 부족하면 검색어와 검색 페이지를 추가한다.
- 수집에 사용한 할당량은 약 1,700유닛으로, 하루 한도 10,000유닛 안에서 수행되었다. `search.list`는 호출당 100유닛이 소모되므로 추가 수집이 필요하면 며칠에 나누어 진행한다.

### 한계와 대응

- 검색 결과의 노출 순서가 인기 영상에 치우칠 수 있다. 검색어를 다양화하였으며, 결과 해석 시 한계로 명시한다.
- 조회수는 수집 시점의 누적값이므로, 같은 영상도 수집 시점에 따라 값이 달라질 수 있다.
- 384개 채널에서 485건이 수집되어 같은 채널의 영상이 여러 개 포함된다. 채널당 영상 수 분포를 확인하고, 특정 채널의 비중이 크면 채널당 영상 수를 제한하는 방안을 검토한다.
- 검색 결과가 최근 업로드 영상에 치우쳐 있어 경과 일수가 짧은 영상의 비중이 크다. 경과 일수를 통제 변수로 포함하고 업로드 후 7일 미만 영상을 제외하여 영향을 줄이되, 결과는 최근 영상에 한해 해석한다.
- 거주자 영상 제외, 여행지 분류, 썸네일 문구 판단에는 연구자의 판단이 들어간다. 기준을 문서로 남기고, 썸네일 라벨링은 일부를 다시 라벨링하여 일치율을 기록한다.
- 썸네일 이미지 파일은 저장하거나 재배포하지 않고 라벨링 결과인 0과 1만 저장한다.

### 준수 사항

YouTube API 서비스 약관과 개발자 정책을 따른다. 댓글 작성자 같은 개인 식별 정보는 수집하지 않으며, 수집한 데이터는 학습 목적의 분석에만 사용한다. 원본 데이터를 GitHub에 공개해도 되는지 약관을 확인하고, 불가능하면 가공한 변수 데이터만 올린다.

## 5. 예상 데이터 구조

### 주요 컬럼

| 컬럼명 | 설명 |
|---|---|
| `video_id` | 영상 고유 번호 |
| `title` | 영상 제목 |
| `published_at` | 업로드 시각, UTC 기준 |
| `duration` | 영상 길이, ISO 8601 형식이며 예시는 PT12M34S |
| `view_count` | 조회수 |
| `channel_id` | 채널 고유 번호 |
| `subscriber_count` | 채널 구독자 수 |
| `thumbnail_url` | 썸네일 이미지 주소 |
| `collected_at` | 데이터 수집일 |
| `title_length` | 제목 글자 수, 공백 포함 |
| `destination` | 여행지 종류, 도쿄 오사카 교토 후쿠오카 기타 |
| `duration_min` | 영상 길이를 분 단위로 환산한 값 |
| `upload_weekday` | 업로드 요일, 한국 시간 기준 |
| `upload_timeslot` | 업로드 시간대, 한국 시간 기준 구간 |
| `days_since_upload` | 업로드 후 경과 일수, 수집일에서 업로드일을 뺀 값 |
| `has_thumbnail_text` | 썸네일 문구 유무, 1이면 있음 0이면 없음 |
| `is_top25` | 조회수 상위 25% 여부, 상위 25%이면 1 아니면 0 |

앞의 9개 컬럼은 API에서 수집한 값이다. `title_length`부터 `days_since_upload`까지 6개와 `is_top25`는 수집한 값을 가공하여 만든 변수이며, `has_thumbnail_text`는 썸네일을 보고 직접 기록한 값이다.

### 변수 구성

위 17개 컬럼 중 식별용 컬럼과 가공 전 원본 컬럼을 제외하면, 분석에 직접 사용하는 변수는 아래 9개이다. `is_top25`는 Q3에서 정답으로만 사용한다.

| 역할 | 변수 |
|---|---|
| 종속변수 | 조회수, 분석 시 로그 변환 |
| 관심변수 | 제목 길이, 여행지 종류, 영상 길이, 업로드 요일, 업로드 시간대, 썸네일 문구 유무 |
| 통제변수 | 채널 구독자 수 로그 변환, 업로드 후 경과 일수 |

### 분석 질문과 데이터의 연결

| 질문 | 사용 컬럼 | 방법 |
|---|---|---|
| Q1 | `view_count`, `destination`, `upload_weekday`, `upload_timeslot` | 박스플롯, 중앙값 비교, 비모수 검정 |
| Q2 | `view_count`, `title_length`, `duration_min`, `has_thumbnail_text`, `subscriber_count`, `days_since_upload` | 단계별 다중회귀 |
| Q3 | `is_top25`, 관심변수 6개, `subscriber_count` | 로지스틱 회귀 |

## 6. 예상 분석 방법

- **전처리:** 결측치, 중복, 이상값을 확인한다. 영상 길이는 분 단위로, 업로드 시각은 한국 시간 기준으로 변환한다. 파생 변수를 만들고 조회수와 구독자 수는 로그 변환한다.
- **Q1:** 여행지, 요일, 시간대별 조회수를 박스플롯과 중앙값으로 비교하고, 비모수 검정으로 차이를 확인한다.
- **Q2:** 구독자 수와 경과 일수를 통제한 단계별 다중회귀를 수행한다.
- **Q3:** 조회수 상위 25%에 속하는지 여부를 로지스틱 회귀로 분류하고, 필요하면 랜덤 포레스트와 비교한다. 경과 일수는 업로드 시점에 알 수 없으므로 입력에서 제외하여 데이터 누수를 막는다.
- **검증:** 회귀 진단으로 잔차와 다중공선성을 확인하고, 학습용과 시험용 데이터를 나누어 교차검증을 수행한다. 썸네일 라벨은 일부를 다시 확인한다.

## 7. 생성형 AI 활용 계획

생성형 AI인 Claude를 프로젝트 전 과정에서 보조 도구로 활용한다. AI가 생성한 코드와 해석은 그대로 사용하지 않고, 실제 데이터와 실행 결과를 기준으로 직접 검증한다.

- **기획 단계:** 분석 질문과 변수 설계를 검토하는 데 사용한다. 실제로 수집 가능한 컬럼과 대조하고, 범위와 변수는 직접 결정한다.
- **데이터 수집 단계:** API 호출 코드 초안을 작성하고 할당량을 계산하는 데 사용한다. 테스트 호출 결과는 직접 확인한다.
- **전처리 단계:** 시간 변환, 제목 글자 수 계산, 여행지 분류 코드를 작성하는 데 사용한다. 분류 결과 일부는 직접 확인한다.
- **EDA와 시각화:** 그래프 코드를 작성하는 데 사용하고, 그래프의 수치는 표와 대조한다.
- **분석 방법 검토 단계:** 검정과 모델 선택 근거를 확인하고 코드를 작성하는 데 사용한다. 가정은 데이터로 직접 확인한다.
- **오류 해결과 결과 해석:** 에러 메시지를 해석하고 해석 문장의 초안을 만드는 데 사용한다. 수치와 그래프에 근거가 있는지 확인하고, 관찰과 해석을 구분하여 작성한다.

사용한 프롬프트와 수정 내용은 기록한다. AI가 작성한 코드는 각 줄의 역할을 직접 설명할 수 있을 만큼 이해한 뒤 사용한다.

## 8. 향후 진행 계획

현재 YouTube Data API 테스트 수집을 마쳤고, 이후 단계는 다음과 같이 진행한다.

- **2차, 10월 말:** 정해진 조건으로 본 수집을 하고 데이터의 구조와 품질을 확인한다. 이후 조건에 맞는 영상만 남겨 전처리하고 파생 변수를 만든다. 썸네일을 직접 보고 문구가 있는지 기록하는 작업도 이때 한다. 마지막으로 여행지, 요일, 시간대별 조회수를 비교하는 탐색적 데이터 분석과 시각화를 수행한다.
- **3차, 11월 말:** 구독자 수와 경과 일수를 통제한 회귀 분석으로 제목 길이, 영상 길이, 썸네일 문구와 조회수의 관계를 확인한다. 업로드 전 정보로 조회수 상위권 영상을 분류하는 모델도 만들고, 학습용과 시험용 데이터를 나누어 성능을 검증한다.
- **4차, 12월 말:** 분석 과정과 결과, 한계, 회고를 최종 보고서로 정리하고 Streamlit으로 핵심 결과를 전달하는 화면을 만든다.

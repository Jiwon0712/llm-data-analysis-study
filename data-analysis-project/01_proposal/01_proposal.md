1. 프로젝트 주제: 한국어 일본 여행 브이로그의 조회수 관련 요인 분석: 제목·영상 길이·업로드 시점·썸네일 문구를 중심으로
2. 해결하고 싶은 문제

관심 현상
한국어로 제작된 일본 여행 브이로그는 유튜브에서 인기 있는 콘텐츠이지만, 같은 주제의 영상이어도 조회수는 수백 회에서 수백만 회까지 크게 차이 난다. 이 조회수 차이가 어떤 요소와 관련되어 있는지 알아보고자 한다.

분석 이유

크리에이터는 제목, 영상 길이, 업로드 시점, 썸네일 등을 직접 선택할 수 있지만, 그 선택이 조회수와 어떤 관계인지는 경험과 감에 의존하는 경우가 많다. 크리에이터가 조절할 수 있는 요소들과 조회수 사이의 관계를 살펴보고, 이 요소들을 변수로 하여 영상 업로드 전에 조회수를 예측할 수 있을지 분석한다.

활용 대상

일본 여행 브이로그를 업로드하려는 크리에이터가 제목, 영상 길이, 업로드 시점을 정할 때 참고하는 자료

한계: 분석 범위가 일본 여행 브이로그로 한정되어 있어 다른 유튜브 컨텐츠에 적용하기는 어렵다. 썸네일의 문구 포함 여부 외에도 조회수에 큰 영향을 미치는 요소들이 많지만, 변수로 설정하기에는 한계가 있어 제외하였다. 

3. 핵심 분석 질문
- 일본 여행 브이로그의 조회수는 여행지 종류, 업로드 요일, 업로드 시간대에 따라 어떻게 다른가?
- 채널 구독자 수와 업로드 후 경과 일수를 통제한 뒤에도, 제목 길이·영상 길이·썸네일 문구 유무는 조회수와 관계가 있는가?
- 업로드 전에 알 수 있는 정보(제목 길이, 여행지 종류, 영상 길이, 업로드 요일·시간대, 썸네일 문구 유무, 구독자 수)만으로 조회수 상위권 영상을 얼마나 구분할 수 있는가?

변수 구성

역할	변수
종속	조회수 (분석 시 log 변환)
관심	제목 길이, 여행지 종류, 영상 길이, 업로드 요일, 업로드 시간대, 썸네일 문구 유무
통제	채널 구독자 수 (log), 업로드 후 경과 일수

4. 데이터 확보 계획

데이터 출처
YouTube Data API v3 (Google 공식 API)

접근 방법
https://developers.google.com/youtube/v3

수집 방법

- search.list로 검색어("일본 여행 브이로그", "도쿄 브이로그", "오사카 브이로그", "교토 브이로그", "후쿠오카 브이로그" 등)를 사용해 영상 ID 목록을 수집한다. 조건은 한국어(relevanceLanguage=ko), 지역 KR, 영상 유형 video, 최근 1~2년 이내 업로드로 한다.
- videos.list로 영상별 제목, 업로드 시각, 영상 길이, 조회수, 채널 ID, 썸네일 URL을 가져온다.
- channels.list로 채널별 구독자 수를 가져온다.
- 수집일을 함께 기록한다(경과 일수 계산용).
- 숏폼(3분 미만)은 제외하고, 여행지가 일본이 아니거나 브이로그가 아닌 영상(광고, 뉴스 등)은 직접 확인해 제거한다.

예상 규모
영상 약 300~500건, 변수 약 10개 내외

주요 컬럼
video_id	영상 고유 번호
title	영상 제목
published_at	업로드 시각 (UTC)
duration	영상 길이 
view_count	조회수
channel_id	채널 고유 번호
subscriber_count	채널 구독자 수
thumbnail_url	썸네일 이미지 주소
collected_at	데이터 수집일
title_length	제목 글자 수
destination	여행지 종류 (도쿄/오사카/교토/후쿠오카/기타)
duration_min	영상 길이(분)
upload_weekday	업로드 요일 (KST 기준)
upload_timeslot	업로드 시간대 (KST 기준 구간)
days_since_upload	업로드 후 경과 일수 (수집일 − 업로드일)
has_thumbnail_text	썸네일 문구 유무 (1: 있음, 0: 없음)

실제 확보 가능 여부

API 키 발급과 테스트 호출로 수집 가능성을 사전에 확인할 예정이다. [확인 필요] 실제로 조건에 맞는 영상이 300건 이상 모이는지 테스트 후 기재.
search.list는 호출당 할당량 소모가 커서(약 100유닛) 일일 한도 안에서 며칠에 나누어 수집한다. [확인 필요] 최신 할당량은 공식 문서에서 확인.
이 데이터로 세 질문에 답할 수 있는지: Q1~Q3에 필요한 변수가 모두 API 응답과 파생 변수, 직접 기록으로 구성되므로 답할 수 있다.

한계와 대응

검색 결과의 노출 순서가 인기 영상에 치우칠 수 있어 선택 편향 가능성이 있다. 검색어를 다양화하고, 한계 항목에 명시한다.
썸네일 이미지 파일은 저장·재배포하지 않고, 라벨링 결과(0/1)만 저장한다.

준수 사항
YouTube API 서비스 약관과 개발자 정책을 따른다. 개인 식별 정보(댓글 작성자 등)는 수집하지 않으며, 수집 데이터는 학습 목적의 분석에만 사용한다. [확인 필요] 원본 데이터를 GitHub에 공개해도 되는지 약관을 확인하고, 불가하면 가공한 변수 데이터만 올린다.

5. 예상 분석 방법
단계	방법	대응 질문
전처리	중복 제거, 결측 확인, 자료형 변환(영상 길이 ISO 8601 → 분, UTC → KST), 이상값 확인, 조회수·구독자 수 로그 변환	공통
기술통계·시각화	조회수 분포, 여행지·요일·시간대별 박스플롯, 그룹별 중앙값과 표본 수	Q1
그룹 비교	Kruskal-Wallis 검정(필요 시 사후검정). 조회수 분포가 한쪽으로 치우쳐 있어 비모수 검정을 사용	Q1
회귀 분석	log(조회수)를 종속으로 하는 단계별 다중회귀(통제 변수 → 제목·영상 길이 → 썸네일 문구 → 여행지·요일·시간대), 다중공선성(VIF)과 잔차 확인	Q2
분류 모델	조회수 상위 25% 여부를 로지스틱 회귀(기본)와 Random Forest(확장)로 분류. 경과 일수는 업로드 시점에 알 수 없으므로 입력에서 제외	Q3
검증	학습/테스트 분리, 교차검증, ROC-AUC·혼동행렬, 구독자 수 포함·제외 모델 비교, 썸네일 라벨링 일부 재라벨링으로 일치율 확인	Q2, Q3

분석 결과는 인과가 아닌 관련성으로 해석하며, 관찰된 결과와 해석을 구분해 작성한다.

6. 생성형 AI 활용 계획
단계	AI 활용	본인 검증 방법
질문 구체화	분석 질문과 변수 설계 검토	데이터로 답할 수 있는 질문인지 실제 컬럼과 대조
데이터 수집	API 호출 코드 초안, 할당량 계산	소량 호출 후 응답 필드를 직접 확인
전처리	시간대 변환, 제목 글자 수, 여행지 분류 코드	변환 전후 샘플을 직접 대조, 분류 결과 일부를 수작업 확인
EDA·시각화	그래프 코드 작성	그래프 수치를 표와 대조
분석 방법 검토	검정·모델 선택 근거 설명	정규성, 다중공선성 등 가정을 데이터로 직접 확인
오류 해결	에러 메시지 해석	수정 후 재실행해 결과 확인
결과 해석·보고서	해석 문장 초안, README 정리	수치와 그래프에 근거가 있는지 확인, 관찰과 해석 분리

AI가 생성한 코드와 해석은 그대로 사용하지 않고, 실제 데이터와 실행 결과를 기준으로 직접 검증한다. 사용한 프롬프트와 수정 내용은 프로젝트 노트에 기록한다.

7. 향후 프로젝트 계획
데이터 확보 (API 키 발급, 테스트 호출, 수집)
→ 데이터 구조·품질 확인
→ 전처리 (파생 변수 생성, 썸네일 라벨링)
→ 탐색적 데이터 분석 (Q1)
→ 본 분석 (Q2 회귀, Q3 분류)
→ 결과 검증
→ 시각화 및 인사이트 정리
→ 최종 결과물 작성
단계	내용
1~2주	API 키 발급, 테스트 호출, 수집 스크립트 작성, 수집
3주	데이터 구조·품질 확인, 전처리, 썸네일 라벨링
4~5주	EDA와 그룹 비교 (Q1)
6~7주	회귀 분석 (Q2), 분류 모델 (Q3)
8주	결과 검증, 한계 정리
9주	Notebook·분석 보고서 작성, Streamlit 결과 전달 화면 제작, GitHub 정리

일정은 학기 일정에 맞게 조정한다. 최종 단계에서는 Notebook과 분석 보고서와 함께, 여행지·요일별 조회수 비교 같은 핵심 결과를 보여주는 간단한 Streamlit 화면을 만들 예정이다.
